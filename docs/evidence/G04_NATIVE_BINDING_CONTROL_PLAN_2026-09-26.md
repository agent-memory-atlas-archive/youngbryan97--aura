# Native role and dependency controls, 2026-09-26

Operation changes alone do not test argument binding or dependency recognition.
These controls keep every primitive and public input fixed while changing one
binding in an otherwise connected three-step program.

## Constructed Source Controls

Each control has 24 pairs, balanced across the existing scalar, lookup, and count
topologies. Both requests use the same definition renderer. Role pairs exchange
the two arguments of one instruction. Dependency pairs change one argument to a
different prior result of the same type. Both programs must return different
exact integer values on their shared public inputs. The final operation is
subtraction in both members, so argument exchange can affect the result.

The generator derives candidates from the existing typed floor. It rejects
disconnected graphs, type mismatches, observationally identical outcomes, and
duplicate source text. A finite generation bound must fill every topology or
refuse the population. It never observes a model score when selecting controls.
The frozen development seed is 1618033.

## Scoring and Verification

The existing target-blind grammar evaluator admits both datasets under a new
version-5 evidence contract. Its model scorer receives the request and proposed
choices, without target programs, values, or construction identities. The
separate verifier reconstructs every request, replays the saved choice scores,
executes the generated graph, and counts exact pairs separately from responses
that merely changed in the expected structural way.

Historical grammar evidence keeps its existing version and population. Existing
definition and equation renderings are unchanged. These controls test causal
source sensitivity within three known computational domains; balanced coverage
and new wording do not prove unfamiliar-domain or frontier transfer.

Thirty-six focused tests passed across graph generation, the two prior source
forms, evaluator dispatch, and independent verification. Model measurements are
pending. The source-erasure training arm uses a separately bound implementation
and continues unchanged while these CPU-only controls are prepared. G04 and G06
remain open.
